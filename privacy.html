Privacy notice

Last updated: 29 October 2026 · Operator: fropic · Scope: personal, single-user project

This notice describes the information website and the intended local Oura integration. The integration is being set up; this website itself does not connect to an Oura account.

1. Data and purpose

With the owner's authorization, the integration may retrieve sleep, activity, readiness, heart rate, HRV, workout, tag, blood oxygen, stress, and heart-health data that Oura makes available under the granted permissions. Profile information or session data is optional and will only be requested if needed.

The purpose is personal wellness tracking, trend summaries, and exploration of associations between habits and recorded measurements. The project does not offer medical diagnosis or public user accounts.

2. Local storage and authorization

The planned integration stores downloaded records and analysis outputs on the owner's computer. OAuth credentials and tokens are kept separately from the public website and must not be committed to its GitHub repository. Local access depends on the owner's operating-system account and security settings.

3. AI-assisted analysis

When the owner requests analysis through ChatGPT or Codex, selected health records or summaries are sent to OpenAI for processing. Those selected inputs are therefore not processed exclusively on the local computer. Provider-side handling and retention depend on the service, account settings, and applicable OpenAI policies. The owner should submit only the records needed for a requested analysis.

Relevant provider notices: OpenAI Privacy Policy and Oura Privacy Policy.

4. Public website and hosting

This static website is intended to be hosted on GitHub Pages. It contains no health-data forms, application analytics scripts, or tracking cookies set by this project. GitHub may process visitor technical information, such as IP addresses and request logs, under its own privacy statement. Public website files contain project information only.

5. Retention and deletion

Local records and reports remain until the owner deletes them, including any copies in backups. There is no automatic deletion schedule in this initial design. The owner can stop syncing and revoke the application's Oura authorization. Revocation prevents subsequent authorized access but does not itself delete existing local files or copies already submitted to an AI service. Provider-side records must be managed through that provider's controls.

6. Sharing and contact

This project does not sell health data or publish health records on this site. External processing described above occurs when the owner chooses AI-assisted analysis. The project is maintained by fropic; the private contact email supplied in the Oura application registration is the application's support contact. Do not post health information or credentials in public GitHub issues.

7. Changes

This notice will need to be updated before introducing new data uses, hosted health-data storage, additional processors, or access for other users.
